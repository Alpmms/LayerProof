# Final website handoff
> Final document. LayerProof public website, final release of 2026-10-07. Later changes are ordinary content or product updates.

## What the website is
The public face of LayerProof: a static site that explains the product with screenshots of the real application, states
the scientific results as recorded (including the negative ones), and invites pilot and data collaboration. It contains
no application code, no backend and no data files.

## Final architecture
- Plain HTML and CSS generated by one Node script, `build.mjs`. No framework. No runtime dependencies.
- Two development-only packages (`playwright`, `@axe-core/playwright`) for the browser check. `package-lock.json` pins them.
- Pages are template modules in `src/pages/`; layout and shared parts in `src/site.mjs` and `src/pages/_parts.mjs`.
- Every number is rendered from three frozen files in `src/data/`: `results.json` (field-trial study and retrospective
  check), `external_validation.json` (EXTVAL_1.0.0), `external_spatial.json` (NCHRP933_SPATIAL_1.0.0).
- Relative links throughout, so the site works under any repository name or custom domain. `404.html` is the only page
  that uses the base path.
- No cookies, no analytics, no third-party requests. Fonts are self-hosted.

## Pages and navigation
Home · Product · Evidence · Research · Pilot · Team · Contact, plus a 404 page. A Demo menu item appears only when a
hosted demo URL is configured.

Home sections, in order: hero; problem; how it works (Project, Data, Evidence, Map, Science, Verify, Pilot); product
screenshots; evidence support and abstention; what the evidence showed; verification candidates and
`EVIDENCE_GAP_PRIORITY`; retrospective check; external evidence; External Spatial Benchmark — NCHRP 933 / MnROAD;
pilot workflow (Import, Validate, Evidence, Support, Verify, Field test, Update); provenance and trust; capabilities;
team; contact.

## Commands
| Purpose | Command |
|---|---|
| Install (only for the browser check) | `npm ci` |
| Syntax and render check | `npm run typecheck` |
| Build | `npm run build` |
| Preview the build | `npm run preview`, then open the address it prints |
| Static checks | `npm run check` |
| Everything above in one step | `npm test` |
| Layout, accessibility, keyboard, 404 | `npm run check:browser` |
| Export the public copy | `npm run content` |

Node 20 or newer. The build itself needs no installed package.

## Deploy
1. Create a public repository and push the contents of the website folder as its root.
2. Settings, Pages, Source: GitHub Actions.
3. The workflow `.github/workflows/deploy-pages.yml` runs on every push to `main`: syntax check, build, static checks,
   upload, deploy. A failed check stops the deployment.
4. Set the repository variable `CONTACT_EMAIL` (or `CONTACT_FORM_URL`). Set `DEMO_URL` only when the demo is hosted.

Details: `FINAL_GITHUB_PAGES_GUIDE.md` and `FINAL_DEPLOYMENT_GUIDE.md`.

## Custom domain
Settings, Pages, Custom domain; create the DNS record GitHub shows (a `CNAME` to `<owner>.github.io` for a subdomain,
or the four `A` records for an apex domain); wait for the certificate; tick Enforce HTTPS. The workflow picks up the
new address for canonical links, the sitemap and the social image. Nothing in the source names a domain.

## Relationship to the live demo
The demo is a separate deployment of the real application in read-only mode with real seeded data. The website links
to it only through `DEMO_URL`. Without that value no demo link is rendered and the capability table states that the
demonstration is not publicly hosted. The demo is packaged and tested; **hosting is required**
(`FINAL_LIVE_DEMO_GUIDE.md`).

## Where the evidence claims come from
The accepted result tables of the application repository, copied into `src/data/` by scripts and compared with their
originals by `tools/check.mjs` and by the application's tests. `FINAL_SOURCE_LOG.md` lists every source.
